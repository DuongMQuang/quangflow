## Phase 1: adopt-feature-extractor agent definition (REQ-006)

**Owner:** dev-new-agents
**Deliverable:** `agents/adopt-feature-extractor.md` + `plugins/quangflow/agents/adopt-feature-extractor.md`

### Tasks
- [ ] Define agent role, inputs (ScannerFindings + FileMap + PreScanAnswers), and output schema
- [ ] Specify feature detection strategy:
  - Directory-based: each top-level source directory = candidate feature
  - Import-based: trace import graphs from entry points to identify feature clusters
  - Naming-based: consistent naming patterns (e.g., `auth/`, `payments/`) signal features
- [ ] Define `FeatureUnits` output schema matching DESIGN.md spec:
  - `name`, `description`, `status` (inferred/confirmed), `confidence` (high/medium/low), `files`, `dependencies`, `notes`
- [ ] Define confidence scoring rules for features:
  - Dedicated directory + clear naming = `confirmed`, `high`
  - Import cluster with consistent naming = `inferred`, `medium`
  - Single file or ambiguous grouping = `inferred`, `low`
- [ ] Define supplemental read budget: up to 20 additional files beyond scanner's FileMap
- [ ] Define Feature Memory Unit template output (one per feature) for scaffolder to consume
- [ ] Handle edge case: no clear features detected → return single "monolith" feature with `confidence: low`
- [ ] Handle edge case: scanner failed → use PreScanAnswers only, all features `confidence: low`

### Acceptance Criteria
- Agent receives ScannerFindings + FileMap and returns FeatureUnits YAML
- Each feature has status (inferred/confirmed) and confidence score
- Supplemental reads stay within 20-file budget
- Agent does NOT write files — returns data to orchestrator

### Done Criteria

## Phase 3: Scanner adaptive sizing upgrade (REQ-008)

**Owner:** dev-upgrades
**Deliverable:** Updated `agents/adopt-scanner.md` + `plugins/quangflow/agents/adopt-scanner.md`

### Tasks
- [ ] Add adaptive sizing step BEFORE existing scan strategy (new Step 0):
  - Count total files (recursive, exclude node_modules, .git, dist, build, __pycache__, venv, .venv)
  - Determine tier: small (<50), medium (50-500), large (500+)
  - Report tier + budget to user before scanning
- [ ] Modify existing scan steps to respect tier budgets:
  - Small tier: no changes — read all (existing M1 behavior)
  - Medium tier: read all manifests + configs + entry points + sample 20% of source files
  - Large tier: read manifests + configs + entry points + key modules only (up to 100 files)
- [ ] Add sampling strategy for medium/large tiers:
  - Always: manifest files, config files, entry points, README
  - Priority: files imported by entry points, test files, interface/type definition files
  - Sample: random selection from remaining source files (seeded for reproducibility)
- [ ] Add `FileMap` to output alongside existing `ScannerFindings`:
  - `total_files`, `tier`, `files_read`, `files_sampled`, `files_skipped`, `scan_coverage`
- [ ] Add post-scan transparency report: what was/wasn't scanned
- [ ] Preserve ALL existing M1 scan steps and output schema (backward-compatible)
- [ ] Handle edge case: file count changes during scan (files created/deleted) → use initial count

- Scanner correctly determines tier from file count
- Small projects behave identically to M1 (regression-safe)
