## GAP-001: `feature_units` vs `features` — UnifiedProjectModel field name mismatch

| Attribute | Value |
|-----------|-------|
| **GAP-ID** | GAP-001 |
| **Severity** | Critical |
| **Status** | Open |

### Description

The orchestrator (`adopt.md`) builds `unified_model.features[]` during inline synthesis (Step 5). Contract 12 (UnifiedProjectModel Schema) also names this field `features`. However, the scaffolder (`adopt-scaffolder.md`) declares its UnifiedProjectModel input with the key `feature_units` — not `features`. The scaffolder then checks `if feature_units is available` before populating `.memory/`, which means on every normal run the scaffolder will NOT find `feature_units` (because the orchestrator sends `features`) and will incorrectly set `feature_extractor_failed: true`, silently skipping all `.memory/` population.

**Impact:** REQ-006 (Feature extraction, `.memory/` population) fails silently on every run where feature extraction actually succeeded. The user receives no error message — they simply see empty `features_populated: []` in DraftArtifacts and no `.memory/` units created, even though the feature extractor ran and produced data.

### Affected Files

- `agents/adopt-scaffolder.md` — lines 16, 30, 191, 193, 201, 207, 308, 333 (all reference `feature_units`)
- `plugins/quangflow/agents/adopt-scaffolder.md` — same (plugin mirror, identical)
- `commands/qf/adopt.md` — line 219 (produces `features`, which is correct per contract)
- `skills/qf/adopt/SKILL.md` — same as adopt.md (mirror)
- `plugins/quangflow/skills/qf/adopt/SKILL.md` — same (mirror)

### Root Cause

dev-upgrades (scaffolder owner) used `feature_units` as the internal field name — presumably treating it as a compound noun for clarity. dev-orchestrator (orchestrator owner) followed Contract 12 exactly and used `features`. The field name was not coordinated across dev boundaries.

### Proposed Remediation

**Fix in `agents/adopt-scaffolder.md` and its plugin mirror:**

1. In the M2 input schema block (under `### M2 (primary): UnifiedProjectModel`), rename:
   - `feature_units: []` → `features: []`
   - Update comment to: `# M2 FeatureUnits (from adopt-feature-extractor; may be absent)`

2. Replace all internal references from `feature_units` to `features`:
   - Section header: `## .memory/ Population (M2 — if feature_units present)` → `if features present`
   - Condition: `If feature_units is available` → `If features is available`
   - Loop: `for each feature in feature_units` → `for each feature in features`
   - Confidence badge note: `from feature_units` → `from features`
   - Output schema comment: `feature_units were unavailable` → `features were unavailable`

3. Sync the change to `plugins/quangflow/agents/adopt-scaffolder.md` (mirror).

**No changes needed to orchestrator or other files** — they already use `features` per the contract.

## GAP-002: `synthesis_conflicts` vs `conflicts` — UnifiedProjectModel field name mismatch

| Attribute | Value |
|-----------|-------|
| **GAP-ID** | GAP-002 |
| **Severity** | Moderate |
| **Status** | Open |

### Description

The orchestrator (`adopt.md`) builds `unified_model.conflicts[]` during inline synthesis (Step 5). Contract 12 specifies this field as `conflicts`. The scaffolder (`adopt-scaffolder.md`) declares its UnifiedProjectModel input with the key `synthesis_conflicts` (line 18). If the scaffolder ever uses this field to trigger conflict-aware behavior, it will read an empty/absent value and apply incorrect logic.

In M2 as written, the scaffolder does not appear to contain explicit logic that branches on `synthesis_conflicts` / `conflicts` (the conflict data flows through to the review gate display, which is orchestrator-handled). The immediate functional impact is lower than GAP-001. However, it is a contract violation that will cause problems if any future scaffolder logic checks conflict state (e.g., to add warnings to CONTEXT.md or lower confidence scores based on active conflicts).

**Impact:** Contract 12 violation. Future scaffolder enhancements that reference conflict state will behave incorrectly if the field name is not corrected. Review gate conflict display is unaffected (handled by orchestrator, not scaffolder).

### Affected Files

- `agents/adopt-scaffolder.md` — line 18 (declares `synthesis_conflicts`)
- `plugins/quangflow/agents/adopt-scaffolder.md` — same (mirror)
- `commands/qf/adopt.md` — produces `conflicts` (correct per contract)
- `skills/qf/adopt/SKILL.md` — same (mirror)
- `plugins/quangflow/skills/qf/adopt/SKILL.md` — same (mirror)

### Root Cause

Same coordination gap as GAP-001 — dev-upgrades chose a more descriptive field name (`synthesis_conflicts`) that diverges from the contract's `conflicts`. The contract name was not enforced at the dev boundary.

### Proposed Remediation

**Fix in `agents/adopt-scaffolder.md` and its plugin mirror:**

1. In the M2 input schema block (under `### M2 (primary): UnifiedProjectModel`), rename:
   - `synthesis_conflicts: []` → `conflicts: []`
   - Update comment to: `# reconciliation conflicts from orchestrator synthesis step`

2. Sync the change to `plugins/quangflow/agents/adopt-scaffolder.md` (mirror).

**No changes needed to orchestrator or other files.**
